## Upload and save

**Content → Add VOD**, including uploads inside **Series → Manage series**, checks
R2 setup. When server credentials are configured, R2 becomes the default for new
uploads. Existing drafts keep their original provider. The Video storage section
lets an admin choose Supabase instead. R2 currently accepts finished MP4s up to
**10 GiB** (an application limit), in 16 MiB parts with progress, retry and
pause/resume while the page stays open. No encoding or adaptive HLS is supplied.

The browser gets short-lived URLs for individual parts and sends bytes directly
to R2. The Edge Function never receives video bytes. Completion checks the
server-reported part count/sizes and final object size/content type before the
registry becomes ready. A failed upload is never publishable. Resuming after
page reload is not implemented; unfinished multipart uploads expire via the
bucket's seven-day rule. Completed unsaved drafts still use session storage.

`r2_vod_uploads` has RLS with admin-only SELECT. Client roles cannot insert or
update verification records; only the server can mark a completed object ready.
`save_uploaded_vod` uses this verified record for R2 uploads and its existing
Storage check for Supabase uploads. The same transaction/idempotency behavior
is preserved, and normal catalog access policies still apply.

## Viewer playback

Catalog URL: `<dev-supabase>/functions/v1/r2-vod/play/<upload UUID>` — a durable
reference, **not a public media URL**. Browser and Apple TV recognize it, call the
POST signing action with the current user's JWT, and pass only the returned R2
signed GET URL to the media player. Guests cannot request playback. The function
checks the caller's RLS-visible movie/episode reference before signing; admin
previews can sign a completed unlinked upload. Default playback expiry is six
hours; admin snapshot/preview callers can request shorter lifetimes.

Signed links are bearer URLs until expiry, not DRM. This uses R2's S3 endpoint;
no public r2.dev domain is required. CORS does not grant access without a valid
signature. Native tvOS is not subject to browser CORS.

## Provider organization for new uploads

Choose **Content provider** before choosing the MP4 in Add VOD (including the
series workspace). Provider options come from Partners → Content partners.
Peep-managed uploads are the default. New object keys are:

```
providers/{provider-id}/deliveries/{upload-id}/playback/{version}-{filename}.mp4
providers/peep/deliveries/{upload-id}/playback/{version}-{filename}.mp4
```

These prefixes are virtual folders; no empty folders need to be created in R2.
The upload ID remains stable when the admin later chooses a movie or episode.
The catalog and upload registry provide the title/series relationship, so saving
or renaming content does not require copying a large video into another folder.
Existing `inbox/` objects and catalog references stay valid. Do not manually move
objects in the Cloudflare dashboard: the registry records their exact keys.

The Add VOD selector organizes admin-managed uploads. Provider self-service
uses the separate Provider Deliveries workflow below; bucket credentials are
never shared.

Provider self-service is now implemented in FARRIS dev under **Partners → Provider
deliveries**, with the provider portal at `/deliveries`. Membership is assigned
explicitly per Peep account; no bucket keys are shared. See
[VOD delivery workflow](VOD.md#provider-deliveries-farris-dev). Its private asset
roles are `video`, `poster`, `hero`, `trailer`, and `captions`. Only explicit admin
publication exposes the poster and attaches the private video to the catalog.
